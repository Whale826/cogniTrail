先消除你的焦虑

你最终要做出来的东西，不是一个复杂软件。它是一个 几百行的 Python 小工具：读一段代码改动 → 调用一次大模型 → 输出几个 Markdown 文件。市面上很多"看起来很大"的项目，核心逻辑也就这么多。难的不是代码，是想清楚要输出什么——而这件事你在设计方案里已经做完了。

三个救命习惯（比任何技术都重要）

  1. 报错信息整段复制去搜。红色的一长串英文，直接整段粘到搜索引擎或问 AI（包括问我），不要自己瞎猜。
  2. 改之前先存一份。要动别人的代码前，先复制整个文件夹改名加 _backup。搞砸了能立刻退回。
  3. 一次只改一个地方。改三处再运行，报错了你不知道是哪处的问题。

2.2安装 Git

让电脑能和 GitHub 通信的工具免费

做什么
Git 是"版本控制"工具，负责把你电脑上的改动同步到 GitHub。没有它，第 4 章、第 8 章都做不了。
去哪
https://git-scm.com/download/win（打开后会自动开始下载，文件名叫 Git-x.x.x-64-bit.exe）
怎么做
1. 双击下载的 .exe
2. 一路点 Next 就行，只有两个地方留意一下：
  · 问你默认编辑器时 → 下拉选 Visual Studio Code（如果列表里还没有，就保持默认的 Vim，以后能改）

3.4打开一个陌生项目，先看这三个地方

不要一上来就点进代码文件夹，会被淹没。按这个顺序：

  1. README.md（首页往下滚）——它回答"这是什么、怎么装、怎么跑"。
  2. 根目录的文件列表——看有没有 package.json（JavaScript 项目）或 requirements.txt / pyproject.toml（Python 项目）。有哪个，就知道该用 npm 还是 pip 装依赖。
  3. src/ 或 lib/ 目录——真正的代码在这。先别读，只数一下有几个文件，感受规模。

想让 AI 帮你读别人的项目？

把仓库链接丢给我（或任何 AI 助手），说："读一下这个仓库，告诉我它的核心模块有哪些、数据怎么流动、我想实现 X 功能应该改哪里。" 这比自己啃快十倍。但记住：最终要能自己讲出来——那正是你这个项目想解决的问题。

四把东西搬到自己电脑上clone

这一章的核心动作就两个词：fork（复制到你账号下）和 clone（下载到你电脑上）。

4.1Fork：先复制一份到你自己的账号

以 claude-mem 为例

做什么
在别人的仓库页面右上角，点 Fork 按钮 → 下一页点 Create fork。几秒后，你会被带到 github.com/你的用户名/claude-mem——这是你的副本，随便改。
为什么
直接改别人的仓库你改不动（没权限）。Fork 之后你有了自己的版本，还能在将来给原作者提改进建议（叫 Pull Request）。
成功标志
页面标题变成 你的用户名/claude-mem，且下方标注 "forked from thedotmack/claude-mem"

4.2Clone：下载到你电脑

先建一个专门放代码的文件夹，比如 D:\code。然后在里面右键 → Open Git Bash here（如果右键里没有，就打开 Git Bash 后用 cd 命令进去）。

# 1) 进入你放代码的文件夹（把路径换成你自己的）
cd /d/code

# 2) 把你 fork 的仓库下载下来
#    地址在你自己 fork 后的页面上，点绿色 "Code" 按钮 → 复制 HTTPS 那一行
git clone https://github.com/你的用户名/claude-mem.git

# 3) 进去看看
cd claude-mem
ls

另一种更简单的做法（不用命令行）：在 VS Code 里按 Ctrl+Shift+P → 输入 git clone → 回车 → 粘贴地址 → 选一个文件夹 → 完成。

4.3打开项目、认出它的结构

在 claude-mem 文件夹里右键 → 通过 Code 打开。左边会出现文件树。你会看到类似这样的东西：

claude-mem/
├── package.json          ← 项目的"身份证"，记录了它依赖哪些包
├── README.md             ← 说明书
├── src/                  ← 真正的代码在这里
├── scripts/              ← 安装、构建用的脚本
└── docs/                 ← 文档

4.4让它跑起来（三步，通用套路）

记住这个万能三步，任何项目都适用

第一步：装依赖（下载别人写好的包）→ 第二步：构建（把源码编译成能跑的东西，有些项目不需要）→ 第三步：启动。具体命令去 README 里找，通常在开头就有。

# 在 VS Code 里按 Ctrl+` 打开内置终端，然后：

# 第一步：装依赖（如果你看到 package.json 就用这个）
npm install

# 第二步：构建（README 里写了 build 才需要）
npm run build

# 第三步：启动（命令看 README，可能是 dev / start）
npm run dev
成功标志
终端不再刷屏，停在某一行不再动，或者打印出一行 "Server running on ..." 之类的字。没报红色错误 = 成功。

4.5跑不动？降级策略（这很正常）

如果 claude-mem 这种 10 万星项目把你劝退了，走这条路

你不需要把别人的大项目跑起来才能做知迹。降级方案是：

  • 在 GitHub 上只读它的 README 和目录结构，看懂它"钩子 → 摘要 → 本地库"这个思路；
  • 自己新建一个空文件夹，从零写你自己的小工具；
  • 需要"抄格式"的时候，去把 AgDR 那份字段规范复制粘贴过来用。

"站在前人肩膀上"不等于"必须 fork 别人的代码"。借用他们的设计思路 + 公开的文件格式，同样成立，而且对新手友好得多。第 5 章就是教你这个。

五组装你自己的知迹：到底"组合"什么assemble

你说要"去组合"，这一章讲清楚：组合的不是代码，是三样东西——格式、坐标写法、外壳形态。这样既站上了前人的肩膀，又不会被许可证和复杂度拖死。

5.1先建立一个正确的认识

新手常以为"二次开发"＝把 A 项目的代码和 B 项目的代码拼起来。这件事对老手都很难（两个项目的技术栈、数据结构往往对不上）。对你有用的组合是这样的：

5.2借法一：文件格式（照抄字段名）

去 github.com/me2resh/agent-decision-record 看它的字段设计。你的决策卡片就用类似的字段，不要自己另发明一套。示例：

---
# docs/decisions/2026-10-14-登录令牌过期策略.md
id: D-20261014-01
file: src/auth/session.ts
lines: 42-58
decision: 令牌过期后改用刷新令牌续期，而不是强制重新登录
why: 强制重登会让用户丢失正在填写的表单，实测退出率高
alternatives: 延长过期时间（被否，安全性下降）
risk: 刷新令牌若被窃取，攻击窗口从小时级变天级
status: active
created: 2026-10-14
---

好处：格式是公开标准，答辩时你可以说"我采用 AgDR 规范"，一句话就显得专业；将来别人也能读你的记录。

5.3借法二：证据坐标（最关键的一条）

为什么这条是你的生命线

你的方案里，防"AI 编造解释"的唯一手段就是每张卡片必须钉住 文件:行号，且这个坐标能被脚本验证。定位不到的，丢弃、不展示。
这个写法别人已经在用，你照抄格式即可，判断逻辑（"定位不到就丢弃"）是你自己写的——这正是你方案里的"闸门"。

实现上，就是用几行代码去验证一句坐标是真是假：

def evidence_ok(repo_root, file_path, line_no):
    """返回 True 表示这条证据真实存在"""
    full = os.path.join(repo_root, file_path)
    if not os.path.isfile(full):
        return False
    with open(full, encoding="utf-8", errors="ignore") as f:
        total = sum(1 for _ in f)
    return 1 <= line_no <= total

5.4借法三：外壳形态（抄思路不抄代码）

去看 claude-mem 的 README，理解它这条链：

事件发生 → 钩子捕获 → 压缩成摘要 → 存本地库 → 下次自动取出

你的版本，把其中两处换掉就是知迹：

代码改动 → 提取决策点 → 生成决策卡片 → 存进你自己的仓库 docs/decisions/ → 3 天后弹问题问你
                        （它压缩给你看的是"摘要"，你产出的是"可被追问的卡片"）
                        （它的去处是"下次给 AI"，你的去处是"给你自己复测"）

6.1增量一：决策卡片生成器

它做什么：读一段代码改动 → 让大模型找出"这里做了什么选择、为什么" → 输出成卡片文件。

在 src/ 下新建 cardgen.py：

import os, json, subprocess, datetime, re
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()                      # 读取 .env 里的密钥
client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")

REPO = r"D:\code\你的测试项目"     # ← 改成你要分析的项目路径
OUT  = os.path.join(REPO, "docs", "decisions")


def get_diff(repo, base="HEAD~1", head="HEAD"):
    """取出最近一次提交的代码改动"""
    r = subprocess.run(["git", "-C", repo, "diff", base, head, "--unified=3"],
                       capture_output=True, text=True,
                       encoding="utf-8", errors="replace")
    return r.stdout


def split_by_file(diff_text):
    """把整份 diff 按文件切开，每个文件一块"""
    blocks, cur = [], []
    for line in diff_text.splitlines():
        if line.startswith("diff --git") and cur:
            blocks.append("\n".join(cur)); cur = []
        cur.append(line)
    if cur:
        blocks.append("\n".join(cur))
    return blocks


PROMPT = """你是代码决策留痕助手。下面是一处代码改动的 diff。
只输出 JSON，不要任何多余文字，格式：
{{"file": "文件路径", "lines": "起始行-结束行",
 "decision": "这次改动做了什么选择（一句话）",
 "why": "为什么这么做（必须具体，禁止写'为了更好'这类空话）",
 "alternatives": "还考虑过什么、为什么没选",
 "risk": "这个决定的风险或代价"}}
如果这处改动没有可提取的决策（纯格式化、改名、加注释），返回 {{"skip": true}}。

diff：
"""


def ask_llm(chunk):
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": PROMPT + chunk}],
        temperature=0.2,
    )
    raw = resp.choices[0].message.content.strip()
    raw = re.sub(r"^```(?:json)?|```$", "", raw, flags=re.M).strip()
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        return {"skip": True}


def check_evidence(repo, card):
    """闸门：证据坐标定位不到 → 丢弃这张卡"""
    fp = card.get("file")
    if not fp or not os.path.isfile(os.path.join(repo, fp)):
        return False
    return True


def write_card(idx, card):
    os.makedirs(OUT, exist_ok=True)
    name = f"{datetime.date.today()}-{idx:02d}-" + \
           re.sub(r"[^\w\-]", "_", card["decision"])[:30] + ".md"
    path = os.path.join(OUT, name)
    with open(path, "w", encoding="utf-8") as f:
        f.write("---\n")
        for k in ("file", "lines", "decision", "why", "alternatives", "risk"):
            f.write(f"{k}: {card.get(k,'')}\n")
        f.write(f"created: {datetime.date.today()}\n---\n")
    return path


if __name__ == "__main__":
    diff = get_diff(REPO)
    if not diff.strip():
        print("没有检测到改动，先在这个项目里改点东西并 git commit")
    else:
        kept = 0
        for i, chunk in enumerate(split_by_file(diff), 1):
            card = ask_llm(chunk)
            if card.get("skip"):
                continue
            if not check_evidence(REPO, card):
                print(f"[丢弃] 证据坐标无法定位: {card.get('file')}")
                continue
            p = write_card(kept, card)
            kept += 1
            print(f"[写入] {p}")
        print(f"\n共生成 {kept} 张决策卡片")

6.2增量二：预设问答 + 追问链

为什么不能是"让 AI 解释一遍给你看"

你之前自己指出过这个坑：给解释 ≠ 你学会了。看一段通顺的解释，大脑会产生"我懂了"的错觉，但什么也没留下。
所以知迹不产出解释，产出的是问题——而且是你没法糊弄过去的问题。你把答案说出口或写下来，才算数。

在 src/ 下新建 questions.py：

import json, os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")

# 追问链的四种固定角度 —— 这是你自己设计的"防糊弄"结构
LADDER = [
    ("定位", "你刚说的这个判断，对应代码里哪一行？请给出 文件:行号。"),
    ("替代", "如果不用这个方案，换一个你会怎么做？当时为什么没选它？"),
    ("代价", "这个做法有什么坏处？什么情况下它会出问题？"),
    ("迁移", "如果要在这个基础上加一个新功能，你会从哪个文件开始改？"),
]

Q_PROMPT = """下面是一张代码决策卡片。请针对它出 3 个问题，
用来检验一个开发者是否真的理解了这次改动。
要求：问题必须能被"是/否"以外的方式回答；不能问代码里字面写出的事实；
至少要有一个问题是关于"如果换个做法会怎样"的。
只输出 JSON 数组，例如 ["问题1","问题2","问题3"]，不要多余文字。

卡片：
"""


def make_questions(card_text):
    r = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": Q_PROMPT + card_text}],
        temperature=0.4,
    )
    try:
        return json.loads(r.choices[0].message.content)
    except Exception:
        return []


def print_ladder(card_id, base_questions):
    """打印出'预设问题 + 追问链'，供你拿去练或答辩"""
    print(f"\n=== 卡片 {card_id} ===")
    print("【第一轮 · 预设问题】")
    for i, q in enumerate(base_questions, 1):
        print(f"  {i}. {q}")
    print("【第二轮起 · 追问链（同一角度连问三层）】")
    for name, q in LADDER:
        print(f"  [{name}] {q}")


if __name__ == "__main__":
    path = input("把一张决策卡片文件拖进来，然后回车：").strip('"')
    text = open(path, encoding="utf-8").read()
    qs = make_questions(text)
    print_ladder(os.path.basename(path), qs)

成功标志：运行 python src/questions.py，把 6.1 生成的一张卡片拖进终端回车，屏幕上出现"第一轮预设问题"3 条 + "追问链"4 个角度。

6.3增量三：延迟理解探针（你的杀手锏）

为什么这个模块是全项目最值钱的 30 行代码

我到 GitHub 上查过了："任务做完后隔几天再回来复测"这件事，全网没有任何实现。所有人都盯着"用 AI 的时候别变笨"，没人管"用完之后我到底还记得多少"。
而你自己的处境就是最好的证明：项目做完了，答辩在三个月后，中间没有人问过你任何一个问题。

在 src/ 下新建 probe.py：

import os, sqlite3, datetime

DB = os.path.join(os.path.dirname(__file__), "..", "probe.db")


def conn():
    c = sqlite3.connect(os.path.abspath(DB))
    c.execute("""CREATE TABLE IF NOT EXISTS probes (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        card_id TEXT, question TEXT,
        created_at TEXT, due_at TEXT,
        answered_at TEXT, answer TEXT, score INTEGER)""")
    return c


def schedule(card_id, questions, delay_days=3):
    """把问题排进日程：delay_days 天后再问我"""
    due = (datetime.datetime.now() +
           datetime.timedelta(days=delay_days)).isoformat(timespec="seconds")
    now = datetime.datetime.now().isoformat(timespec="seconds")
    c = conn()
    for q in questions:
        c.execute("INSERT INTO probes(card_id,question,created_at,due_at) VALUES(?,?,?,?)",
                  (card_id, q, now, due))
    c.commit(); c.close()
    print(f"{len(questions)} 个问题已排期，{delay_days} 天后到期")


def due_now():
    """列出今天该问我的问题"""
    c = conn()
    rows = c.execute(
        "SELECT id,card_id,question FROM probes "
        "WHERE answered_at IS NULL AND due_at <= ? ORDER BY due_at",
        (datetime.datetime.now().isoformat(timespec="seconds"),)).fetchall()
    c.close()
    return rows


def answer(probe_id, text):
    c = conn()
    c.execute("UPDATE probes SET answer=?, answered_at=? WHERE id=?",
              (text, datetime.datetime.now().isoformat(timespec="seconds"), probe_id))
    c.commit(); c.close()


if __name__ == "__main__":
    rows = due_now()
    if not rows:
        print("今天没有到期的复测题。明天再来。")
    for pid, cid, q in rows:
        print(f"\n[{cid}] {q}")
        a = input("你的回答：")
        answer(pid, a)
        print("已记录。")

怎么用：生成卡片后，调一次 schedule(card_id, questions, delay_days=3) 把问题排进去；三天后打开终端跑 python src/probe.py，它会一条条问你，你把回答打进去。这些回答的存档，就是你"理解程度随时间变化"的第一手数据——答辩时这比任何说法都有力。

三个增量做完，你就有了一个真东西

不需要界面、不需要插件外壳。一个命令行工具 + 一个文件夹里的卡片 + 一个会来问你问题的数据库，功能上已经完整。后面要不要包装成 IDE 插件，那是"能不能做得更漂亮"的问题，不是"有没有东西"的问题。

七验证：一下午跑完的最小实验validate

如果整份手册你只做一件事，做这件。它的目的是回答那个唯一的真问题：这东西到底有没有用。

为什么非做不可

你过去做的所有东西——设计方案、UML、竞品调研——都是"论证它应该有用"。这个实验是唯一能验证"它到底有没有用"的东西。一下午，成本为零，但它要么给你信心，要么帮你省下两周白干。

7.1实验设计（三句话说完）

表 11　报错 → 原因 → 解决，对照着查

中文显示成乱码编码问题在 Python 文件开头加 # -*- coding: utf-8 -*-；读文件时加 encoding="utf-8"

9.2国内网络加速（这两条命令建议现在就执行）

# pip 换成清华镜像
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 以后 pip 超时就加这个参数
pip install xxx --default-timeout=120
