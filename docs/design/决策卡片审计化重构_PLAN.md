# 决策卡片审计化重构 · 代码 Plan

> 一句话：把「让 AI 自己交代它为什么这么改，我们抄下来」改成
> **「我们当审计师，去核 AI 有没有说实话、关键决策到底是哪几条」。**

---

## 一、为什么要改：现在这套流程缺了哪一环

现在的链路（`cardgen_session.py` / `cardgen.py`）做的是：

1. 把 diff / AI 的自述喂给模型 → 模型**自己**说「我做了什么、为什么、有什么风险」；
2. 我们只校验一件事：它给的 `文件:行号` **真的存在**（`schema.evidence_ok` / `gate`）；
3. 通过就落盘，然后 `curate` 做排序与去重。

用审计的话讲，**我们只做了「凭证核对」，没做「实质性测试」**：

- 卡片上的 `why` / `risk` 全是**被审计方的口述**（管理层声明），我们一个字没核；
- 「这一行存在」不等于「这句话说的是这一行」——行号对得上、理由可以是编的；
- 「这次改动有没有把原有的校验悄悄拿掉」——现在的链路**根本不看**；
- 「几十张卡里哪几条是关键决策」——现在只按时间流水排，没有重要性分层。

所以会出现三种「参假」，而现在一种都拦不住：

| 参假形态 | 现在拦得住吗 |
|---|---|
| **口是心非**：`why` 写「加了兜底」，代码其实是把兜底删了 | 拦不住 |
| **包装凑数**：把格式化 / 改名 / 调试残留包装成「决策点」交差 | 拦不住 |
| **悄悄放水**：删掉校验、吞掉异常、写死密钥、`--no-verify` 硬提交 | 完全看不见 |

## 二、审计骨架 → 本项目的对应关系

「整本书的风险导向」落到这里，就是一条主线：
**先评风险 → 再定重要性 → 再取证 → 再验证 → 最后出意见。**

| 审计概念 | 本项目里对应什么 | 落在哪个模块 |
|---|---|---|
| 被审计单位 / 管理层 | AI（写代码的那一方）；它的自述 = 管理层声明 | —— |
| 会计资料 / 原始凭证 | `git diff`、`apply_patch`、会话原文 | session_source |
| 审计师 | 知迹 + 用户 | —— |
| **风险评估程序** | 先给这次变更画一张风险画像（改了哪些文件、碰了什么面） | `audit.risk_profile` |
| **重要性水平 materiality** | 只记「换个选择结果就不同」的；分层为 关键 / 一般 / 记录 | `audit.materiality` |
| **重大错报风险 / 特别风险** | 数据、并发、金额、权限、默认值、外部网络、序列化 | `audit.risk_tags` |
| **舞弊风险（参假）** | 口是心非 / 包装凑数 / 悄悄放水 → 一组可脚本判定的信号 | `audit.scan_fraud` |
| **控制测试** | 代码原有的校验与兜底这次有没有被动到 | `Card.control` |
| **实质性程序（细节测试）** | 逐条回真实文件核 `quote`；核卡片声称的行为真在代码里 | `gate` + `audit.check_claim` |
| **审计证据的充分性与适当性** | 证据够不够（坐标可否定位、摘录上下文、claim 可否证伪） | `audit.audit_card` |
| **关键审计事项 KAM** | 卡片上的「关键决策」——按 tier 排在最前 | `curate` |
| **审计意见** | 无保留 / 带解释性说明 / 保留 | `audit.opinion` |
| **未更正错报台账** | 被闸门丢弃、以及存疑未处理的条目，**必须列出来** | `curate` + `curate.load_curated` |
| 与治理层沟通 | 预设问答 + 追问链（已有） | questions |

## 三、一条铁律（沿用本项目已有的哲学）

> **凡是脚本能自己算出来的，绝不让模型说。**

理由和 `curate._superseded_from_evolution` 里写的一样：
同一件事让模型说两遍，两遍必然对不上；而算出来的永远不会自相矛盾。

因此本方案把下面这些判定**从模型手里拿走，交给脚本**：

- 关键度 `tier`（模型只能**建议**，脚本按规则**归并**，且 key 不可被降级）
- 可疑信号 `signals`
- 审计核对结论 `verdict`
- 审计意见 `opinion`

模型只管一件事：**说清它做了什么，并给出一条能被代码证实或证伪的断言。**

## 四、要改的文件

### 新增 `src/audit.py`（核心，纯脚本、零模型依赖）

```python
@dataclass
class Subject:            # 被审计对象：一次改动
    file: str; lines: str
    evidence: str         # 证据坐标附近的真实代码
    added: list[str]      # 新增的行
    removed: list[str]    # 删除的行
    commands: list[str]   # 执行过的命令
    session_quote: str    # 只在对话里存在的决策，锚到会话原话

def risk_profile(subject) -> dict                      # 风险评估：改了哪些面
def sensitive_file(path) -> str | None                 # 配置文件 / 密钥 / 迁移 / 认证
def risk_tags(text) -> list[str]                       # 命中的风险面
def materiality(subject, claimed_tier="") -> (tier, why)   # 关键 / 一般 / 记录
def scan_fraud(subject) -> list[dict]                  # 参假痕迹（含严重度）
def check_claim(claim, decision, evidence) -> (ok, why)     # 认定核对
def audit_card(subject, fields) -> dict                # 汇总：tier/signals/verdict
def opinion(cards, dropped) -> dict                    # 出审计意见
```

**参假信号（`scan_fraud`）的判定规则 —— 全部可在本地复算：**

| code | 标签 | 命中条件 | 严重度 |
|---|---|---|---|
| `guard-removed` | 原有校验被拿掉 | 删除行含 `assert/raise/if not/validate/check/guard/>=、<=` 之类保护，且没有等量新增 | 高 |
| `silent-failure` | 吞异常 | 新增行含 `except ... : pass`、`except Exception` + `continue`、`ignore_errors=True`、`except: return None` | 高 |
| `hardcoded-secret` | 写死凭据 | 新增行里出现密钥/口令/令牌字面量（`sk-`、`password = "..."`） | 高 |
| `forced-through` | 绕过流程 | 命令里带 `--no-verify`、`--force`、`--no-gpg-sign`、`chmod 777` | 高 |
| `debug-residue` | 调试残留 | 新增行含 `print(`、`console.log`、`breakpoint()`、`TODO`、`FIXME`、`XXX` | 中 |
| `claim-not-in-code` | 口是心非 | 卡片声称的关键 token（数字 / 标识符）在证据里找不到 | 高 |

> 注意：命中信号 ≠ 判定造假。信号是「值得追问的点」，
> 所以它只做两件事：给卡片打「存疑」标、把这张卡抬进 curate 的「高风险与可疑项」。

### 扩展 `src/schema.py`

- `FIELD_ORDER` 在 `impact` 之后插入四个字段：
  `tier`（key/normal/minor）、`claim`、`control`、`signals`
- `Card.to_markdown()` 增加两节（都为空时不渲染，保持「没填不出空小节」的既有约定）：
  - `## 审计核对` —— 脚本算的结论（证据是否可复核 / claim 是否成立 / 命中的可疑信号）
  - `## 这次改动动到的保护` —— `control`，对应控制测试
- `Card.to_probe_text()` 带上 `tier` 与 `claim`，出题时能直接问「凭什么」

### `src/cardgen_session.py` / `src/cardgen.py`

- 提示词角色从「决策留痕助手」换成「**审计师**」：
  - 先给**风险评估**结论（这一轮改了哪些面、风险在哪），再抽决策点；
  - 每个决策点必须多给一条 `claim`：**能被代码证实或证伪的事实断言**
    （例：「阈值由 0.5 改成 0.35」，里面的 `0.5 / 0.35 / 阈值` 会被脚本回文件核）；
  - 必须回答 `control`：这次改动**依赖或拿掉了哪一层原有保护**；
  - 明确写出「参假」的定义与反例，并允许模型标注「AI 的自述与改动不一致」。
- 落盘前调 `audit.audit_card()` 算出 tier / signals / verdict，写进卡片。
- `gate()` **签名与返回值保持不变**（测试依赖 4 元组），审计在 `gate` 之后独立跑一遍。

### `src/curate.py`

- 顶部多一行 **审计意见**（无保留 / 带解释性说明 / 保留）。
- 新增 `## 五、高风险与可疑项`：把 tier=key 与带回信号的卡片单列，
  **并给出被闸门丢弃的条目台账**（未更正错报不能默默丢）。
- 现有四个小节的标题与顺序**一个字都不动**（测试断言依赖它们）。
- `curated.json` 多落 `opinion` / `key_items` / `suspicious` / `unadjusted` 四段。

### `src/dashboard.py`

- 卡片标签区加：`关键决策` / `记录性` / `存疑`（存疑用告警色）。
- 卡片正文加 `claim` 与 `审计核对` 两段（折进 `<details>`，不撑长面板）。
- 顶部统计区加一格「审计意见」，并加「只看关键」「只看存疑」两个筛选按钮。

### `tools/build_exe.py`

- `HIDDEN` 里加 `"src.audit"`（它会被懒 import，不加在打包后会 ImportError）。

## 五、验收标准

1. **参假拦得住**：造一份「删掉校验 + 吞异常 + 写死密钥」的 diff，
   `audit.scan_fraud` 必须命中对应信号，卡片上出现「存疑」，curate 的第五节列出它。
2. **关键度不可被模型降级**：模型把一张「改了默认密钥读取顺序」的卡片标成 `minor`，
   脚本必须归并成 `key`（因为命中敏感面），并把理由写进卡片。
3. **口是心非留痕**：卡片声称「0.35」，证据行里只有 `0.5` → `claim-not-in-code` 命中。
4. **不回归**：`tests/` 下全部 7 个测试 + `tools/gui_smoke.py` 保持全绿；
   `curate` 的四个小节标题、`gate` 的 4 元组返回值不变。
5. **不空手**：没配 Key（Mock 模式）时，tier / signals / verdict **照样算得出来**——
   因为它们是脚本算的，不依赖模型。

## 六、明确不做的

- 不改 `docs/decisions/` 下已经落盘的卡片（它们是历史凭证，只读）。
- 不让模型判「关键度最终值」——它只能建议。
- 不做代码质量/安全扫描器。信号只服务一件事：**这张卡值不值得你亲自看一眼。**
- 不引入新依赖（沿用标准库 + 现有 `llm` 层）。

## 七、落地情况（0.8.0，已发版）

验收五条全过：8 个测试文件共 **373 项检查**全绿（`test_audit.py` 86 项），
发版三连全过（`python tools/check_exe.py`）。

按计划落地的部分不重复，下面只记**计划里没写到、实现时才发现的**三件事 ——
它们比计划本身更值得留档。

### 7.1 计划外的诚实性漏洞：`is_audited()` 把 `tier` 也算作「已审计」

计划里 `is_audited()` 的判据是「tier / verdict / signals 任一非空」。
实现到插件那一步才发现这是错的：`tier` 模型自己也会填（设计上它
**只许往上抬**），所以「有 tier」根本不能证明「审过」。

而插件形态下 agent 是**手写**卡片的 —— 它写的正是 `tier` + `claim`，
没有 `verdict` / `signals`。于是这批卡片会被判成「已审计」，
在一条可疑都没有的情况下拿到 **无保留意见**。

那还是「把没审计说成审过了」这同一个错，只是换了个入口。
**判据收紧成只认 `verdict` / `signals`**（这两格只有脚本会写）。

### 7.2 计划外的能力缺口：手写卡片一律「未审计」→ 审计等于白装

收紧判据之后暴露了反面的问题：手写卡片全落到「未审计」，
`cognitrail audit` 在插件里就没什么可说的了。

所以补了 `curate.reverify_card()`：拿手写卡片自带的那条 `claim`，
回仓库里核一遍。它刻意做成**不对称**的：

| 核对结果 | 写什么 | 为什么 |
|---|---|---|
| 断言与代码对不上 | 记高危「口是心非」+ 定成关键决策 | 手写流程里最该抓的就是这个 |
| 断言里没有可核对的字面量 | 记「证据不充分」 | 核不了就说核不了 |
| 断言核对**通过** | **什么都不写**，保持「未审计」 | 手写卡片没有 diff，「这次删掉了什么保护」看不见。核对通过 ≠ 审计通过 |

放在 `curate.py` 而不是 `audit.py`：它要用 `schema.parse_lines`，
而 `schema` 反过来 import `audit`（取标签表）—— 放 audit 里就是循环依赖。

### 7.3 「还有几张从来没核过」要在每一种结论里都点名

原来只在给「无保留」时附一句。但正因为它没核过，结论才更该打折；
而给出「保留」意见时，读者最容易以为「反正都查过了」。
现在四种结论都会附上未审计的张数。

### 7.4 顺手固化的工具

- `tools/check_exe.py` —— 发版验证三连（版本号 / PE 子系统 / 窗口版自检）。
  固化它的直接原因：PE 子系统的偏移手算错过一次 ——
  `e_lfanew` + 24（签名 4 + COFF 头 20）= 可选头起点，Subsystem 再 +68；
  漏掉那个 +24 会读出「未知」，然后误判成打包坏了。
- `cognitrail audit` 子命令（主 CLI + 插件入口 `scripts/cognitrail.py`），
  控制台菜单里是 `[10]`。

### 7.5 演示

`out/audit-v2/` 是一份可直接看的样例：3 张卡片混在一起 ——
