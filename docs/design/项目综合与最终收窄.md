# 项目综合：三方合并后的最终定位

> 第八轮。这一轮不新增方向，只做三件事：把 GPT 那份分析里比我强的地方认下来，把它没解决的地方补上，然后合并收窄到一个**一个人能做完**的范围。

---

## 一、先说 GPT 那份比我强的三处

我前面六轮一直在换方向，它没有。它一上来就把标准定对了。这三条应该直接采纳。

### 1. 判断标准换对了

> "前景判断应该建立在**减少返工、加快接手项目、提高审查质量**这些可观察结果上，而不只是'大家担心被 AI 替代思考'。"

我前几轮用的是"认知债"这类概念——它不可直接观察，所以永远争不出结论。**"减少返工"可以数，"加快接手"可以计时，"提高审查质量"可以评。** 这一条是整份文档里最值钱的一句。

### 2. 难度排序更诚实

它指出整个项目的难度集中在「**可靠同步**」——执行状态、幂等、超时、异常——**而不是生成漂亮的解释**。它给"兼容多个 IDE / Agent / 语言"标了**很高**。

这是我这六轮一直低估的地方。我一直在讨论"解释怎么写得准"，但真正难的是"界面上的状态和真实执行状态怎么保持一致"。

### 3. 对照组设计，直接判了我前几版的死刑

> "你的真实竞争对手包含用户**已经能免费或低成本开启**的解释、规划功能。如果只和完全不解释的工具比较，很容易高估产品价值。"

它要求验证时比三组：**「原有 Agent」/「原有 Agent + 计划解释模式」/「你的工具」**。

我前面每一版的方案，相对中间那一组的增量都太小了。**这一条必须写进任何后续验证设计里。**

顺带一句，它还给了一条我以前没有的出口：**"如果理解改善，但没有人愿意为此付费，可能更适合作为教育产品、团队入职工具或现有开发工具的插件功能。"** 这回答了我第四轮纠结的"没人付费"——它可能本来就不该是独立产品。

---

## 二、但它没解决三件事

### 1. 它全部是"过程内"的

它的每一个机制——项目地图、任务进度、决策卡片、选项——都要求你**在 AI 干活的时候在场并做判断**。

但你上一轮说的痛是：

> **"AI 做完一个任务后，我本来就没学会。"**

那一刻已经过去了。**过程内的方案，救不了事后。** 而它的"学习场景"只有一句"偶尔让用户预测结果"——那不是机制，是建议。

### 2. 它的界面是 VS Code 侧栏

第三轮已经论证过：**任何需要用户主动打开的面板，都会被卸载。** 侧栏需要你主动去看，它和弹窗只是摩擦大小的区别。GPT 自己也承认"最大的产品难点：不让用户觉得被打断、被上课"——但它给的解法（侧栏）恰好就是要主动打开的东西。

### 3. 它对"怎么知道用户真的懂了"没有答案

它把"判断用户是否真正理解"标成高难度，然后在验证指标里写"暂时关闭 AI 后解释模块关系""数天后完成相关修改"——**这两条其实是对的，但它没把它变成产品机制**，只当成了实验指标。而"点击选择次数"这种它明确警告不要用的指标，恰恰是侧栏交互的天然产物。

## 三、五处冲突，我的裁决

| 冲突点 | GPT | 我们 | 裁决 |
|---|---|---|---|
| 产品形态 | VS Code 扩展侧栏 | 写文件进仓库 | **写文件。** 侧栏要主动打开→会被卸载；文件是资产，且能对抗"被大平台吸收" |
| 介入时机 | 过程内 | 事后 | **两个都留，但事后为主。** 过程内只保留"关键决策"一处，一周不超过几次 |
| 选项 | 必须真实改变执行，否则是装饰 | 人会一直点默认项 | **第一版整个砍掉选项。** 见下 |
| 判断懂没懂 | 用户点击行为 | 不能问用户 | **都不对。** 唯一可靠的信号是"数天后能不能自己改"（GPT 的指标表里其实已经有这一条，把它提到机制层） |
| 首批用户 | 有编程基础的开发者 | 学生 / 求职者 | **合并：有基础、但对当前项目不熟的人。** 含开发者接陌生仓库、含学生面对自己 AI 做的项目、含求职者面对简历上的项目 |

### 为什么第一版要砍掉"选项"

GPT 说得很对：**"选择必须真实改变执行。用户选了'全部成功才保存'，实现和测试就应当覆盖事务边界和失败回滚；否则选择界面只是装饰。"**

但"让选择真实改变执行"= 需要**执行控制层**（拦截、暂停、恢复、幂等、超时）——而这一层正是 GPT 自己标为最难的部分。

**所以正确的顺序是：既然选项要真实改变执行才不是装饰，而执行控制最难，那第一版就不做选项。**

只做"记录"：AI 已经做了选择，我把那个选择记下来、摆在你面前。**不做"让你选"，只做"让你知道刚才选了什么"。**

这一刀同时砍掉了 GPT 方案里最贵的三块（执行控制、可靠同步、多运行时兼容），也砍掉了我们前三轮反复纠缠的"怎么让人愿意点"。

## 四、收窄：从"开发助手"砍到"一页纸"

GPT 的估算是**两名全职工程师、8–12 周**。**你是一个人。** 所以还要再砍一刀。

砍的依据只有一条：**它对"你能答得上"这个目标，是不是必需且不可替代。**

| GPT 方案里的模块 | 砍不砍 | 理由 |
|---|---|---|
| 项目地图 | **砍** | DeepWiki / tree-sitter 已做，且与"答得上"关系弱 |
| 任务进度视图 | **砍** | 需要可靠同步事件流，GPT 标"高" |
| 决策卡片 | **留** | 核心，不可替代 |
| 选项（真实改变执行） | **砍** | 需要执行控制层，GPT 标"高" |
| 执行控制 / 暂停恢复 | **砍** | GPT 自己说整个项目的难点在这 |
| 持久化决策记录 | **留** | 唯一能跨时间积累的资产 |
| 学习模式（预测） | **留（简化）** | 改成事后一问，不做过程内打断 |
| VS Code 侧栏 | **砍** | 需主动打开 = 会被卸载，改为写文件 |
| 多语言 / 多 IDE / 多 Agent | **砍** | GPT 标"很高" |
| "判断用户是否真正理解" | **留（换实现）** | 不用点击行为，用"数天后能否自己改"做延迟探针 |

**砍完剩下的四件（一个人两周内可做）：**

1. 读仓库 + 读最近的 diff
2. 找出这次改动里的 3–5 个决策点
3. 生成"预设问答卡"（决定 / 理由 / 替代 / 追问链，每句带 `文件:行号`）
4. 写进 `docs/` 并给出一页汇总

## 五、砍掉这些为什么不需要心疼

因为**砍掉的每一块都对应一个已经占位的竞品**：

- 过程内解释 → Cursor（Plan Mode）、Claude Code（Explanatory + Learning）、Kiro
- 静态项目理解 → DeepWiki
- 决策点提取 → AssumptionMiner（arXiv 2607.22898，F1 0.816）
- 轨迹溯源 → Semantica（10.8k star）、h5i
- 风险审计 → iFixAi（19.1k star，32 类风险测试）

**没砍之前，你同时在和这五个打。砍完之后，你只做一件它们都不做的事。**

## 六、一句话定义

> **它不干预 AI 怎么做。它只在你做完之后，告诉你刚才发生了什么、哪几个地方你可能答不上来——写成一份你能带走、能提交、能在现场接住追问的东西。**

更短：

> **不帮你做，也不教你做，只帮你"事后对得上账"。**

用户能直接感受到的承诺（沿用 GPT 的措辞，改一处）：

> 让你知道 AI **已经**改了什么、为什么这样改，以及**哪几个地方你可能会被问住**。

GPT 的原句是"让你知道 AI 正在改什么……以及出了问题如何接手"——它把时态放在进行时。**改成完成时，就是这一轮的收窄。**

---

## 七、验证设计（合并双方）

**对照组必须三组**（GPT 的正确设计）：
1. 原有 Agent
2. 原有 Agent + 计划/解释模式 ← **真正的对手，不能省**
3. 你的工具

**指标**（合并后，删掉所有行为计数）：

| 指标 | 验证什么 |
|---|---|
| 任务完成率、缺陷、返工次数 | 是否改善实际工作 |
| 总耗时、被打断次数 | 理解收益是否值得额外成本 |
| **关掉 AI 后，解释模块关系** | 是否形成宏观认识 |
| **独立定位问题、预测参数影响** | 是否具备接管能力 |
| **数天后完成相关修改** | 理解是否真的保留下来 ← 最硬的信号 |
| 持续使用、愿意付费试点 | 是否存在商业需求 |

明确不用：展开解释次数、点击选择次数、卡片阅读时长。**这些数字好看，什么都不能证明。**

## 八、下一步：一个下午，一个数字

不要写代码，不要做侧栏，不要做选项。

1. 挑你自己一个**用 AI 做出来的**项目
2. 手动跑一遍那四步，写出 3 张卡（每张必须带 `文件:行号`）
3. **拿这 3 张卡来问我。我扮演答辩老师，沿追问链往下问，数你能接住几层。**

判据：
- 接住 1 层就崩 → 卡片有用，它提前标出了你的薄弱点
- 3 张里有 2 张让你"啊，原来是这样" → 这个工具真的在填坑
- 3 张你都觉得"我早知道" → 你没这个痛，停

**唯一的判据是：这些卡片有没有让你在被追问时多接住一层。**

## 附：三方共识清单（可以直接当结论用）

无论后面怎么变，下面这些已经不用再讨论了：

1. **痛点真，但需求不自发转化** → 必须有硬截止日（答辩 / 面试 / 交接）才会被真的使用
2. **必须收窄** → 通用版本必死
3. **第一批用户是"有基础但对当前项目不熟的人"**
4. **决策卡是原子单位**，不是解释段落
5. **最大陷阱是"看过解释 ≠ 掌握"** → 任何以"用户读了"为成功的设计都是错的
6. **必须和"Agent + 计划解释模式"比**，不能和"完全不解释"比
7. **过程内介入会被卸载** → 要么零打断，要么事后
8. **唯一剩的空位是：事后 · 个人 · 一页纸**
