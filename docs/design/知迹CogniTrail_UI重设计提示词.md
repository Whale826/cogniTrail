# 知迹 CogniTrail · UI 重设计提示词

> 用途：把「第 5 节」整段复制给任意生成平台（v0 / Claude / Lovable / Figma AI / 即时设计），
> 让它产出新版界面设计。第 1～4 节是这次改版的**依据**，不要贴给平台，留着自己判断。
> 文末有**精简版**（约 500 字），给有长度限制的平台用。

---

## 1. 先说结论：现在的界面丑在哪

不是配色丑，是**信息没有主次**。三条真问题：

1. **看不出重点。** 43 张卡片被一视同仁地塞进一张表格，关键决策和「改了句注释」长得一模一样。
   用户打开界面想看的是「这次到底有什么要紧事」，界面回答的是「这里是全部东西」。
2. **找不到那件事。** 想核对「这行为什么这么写」，要先选会话 → 定选段 → 点生成 → 在列表里找 →
   读详情。四步之后才看到该看的证据，而这一步本来应该是点一下。
3. **不像能拿去汇报的东西。** 界面上占地最多的是日志、文件路径、`status`、`tone`、一排放不下的按钮。
   用户真正要抄走的是「结论 + 一段能贴进周报的话」，却要自己在术语堆里挑。

一句话：**现在是一个「工具的调试面板」，用户要的是一个「能读、能抄、能交差的结果页」。**

---

## 2. 谁会打开它，他们心里那句话是什么

| 角色 | 场景 | 打开时心里那句话 | 界面必须在 3 秒内回答 |
|---|---|---|---|
| **记录者**（用 AI 干活的人：开发 / 研究者 / 写作者） | 刚干完一段活 | 我刚到底做了什么？值不值得记下来？ | 这一轮改了什么、其中哪几条是**关键决策** |
| **复盘者**（三个月后的本人 / 接手同事 / 导师） | 被问到细节 | 当时为什么这么定？后来怎么变的？ | 为什么、还考虑过什么、代价是什么、被谁推翻 |
| **审查者**（技术负责人 / 合规 / 自己起疑心时） | 抽检 | 这批东西能不能照单全收？ | 审计意见 + **可疑痕迹** + 证据原文（点得开） |

三种人共用同一屏，但**优先级不同**：默认先服务第三种（结论最硬），再服务第一种（看得见的产出），
最后才服务第二种（明细折叠）。

## 3. 想看的 / 不想看的

这是本次设计的唯一取舍依据。凡是「不想看」的，要么删掉，要么折叠一层。

### 3.1 真的想看的（按价值排序）

| # | 内容 | 为什么值钱 | 界面要求 |
|---|---|---|---|
| 1 | **一句话结论**：无保留 / 带解释性说明 / 保留 | 这是用户唯一真正需要的判断 | 首屏最大的字，配 4 个数字 |
| 2 | **4 个数字**：关键决策 N 条 · 需人工复核 N 条（其中存疑 N 条）· 未审计 N 条 · 未取证 N 条 | 一眼知道规模和工作量 | 一横排统计块，可点，点了筛列表 |
| 3 | **可疑痕迹**（拿掉校验 / 吞异常 / 写死凭据 / 绕过流程 / 断言与代码对不上） | 唯一「出事前能发现」的东西 | 单列一区，红色系但克制，每条一句人话 + 出处 |
| 4 | **关键决策**（不是全部卡片） | 决定后面所有事的那几条 | 卡片式，一条一屏宽的三分之一高，按重要性排 |
| 5 | **证据坐标**（`文件:行号` + 原话摘录） | 不服气的人要能自己查 | 等宽字体，可点，点开显示原文片段 |
| 6 | **演进**：早期做法为什么被否 → 现在是什么 | 「学到了什么」就在这里，也是交接的答案 | 时间轴 / 链条，前后的卡片用箭头连起来 |
| 7 | **项目走到第几步、卡在哪** | 让几十张卡片拼成一张地图，而不是碎片 | 阶段条：阶段名 + 该阶段卡片数 + 该阶段卡点 |
| 8 | **能直接抄走的一段话** | 周报 / 论文 / 交接文档要用 | 每条决策右上角一个「复制」按钮 |
| 9 | **来源与时间**（哪一轮、哪个工具） | 追溯用，但不必常驻 | 次要字号，或 hover 才显现 |

### 3.2 不想看的（现在恰恰占版面最多）

| 不想看的内容 | 为什么 | 怎么处理 |
|---|---|---|
| 日志流（`text_log`） | 排错用的，用户 95% 的时间不看 | 从主界面移走，收到右下角的「活动 / 出错了」抽屉，**默认折叠** |
| 卡片元信息（`status` / `tone` / `path` / `created` / `id`） | 机器字段 | 折进「详情」最底部，默认折叠 |
| 会话原文全文 | 太长，而且是**中间物**，不是结果 | 降级为「看原文」按钮，按需在侧边抽屉打开 |
| 一排开关（3 个来源勾选 + 项目过滤 + 自动生成 + 清空日志 + 自检…） | 每加一个开关，主流程就模糊一分 | 设置收进右上角齿轮；主界面最多留 1 个全局开关（来源） |
| 模型的自述与感想 | 用户要的是「做了什么 / 为什么 / 代价」 | 不要出现「我认为」「值得注意的是」这类句子占版面 |
| 术语黑话：闸门 / 锚点 / quote / tier / verdict / superseded | 小白模式的用户根本不知道是什么 | 界面上**永远说人话**，术语只出现在「专家细节」里 |
| 教科书式空状态（一大段「什么是决策卡片」） | 用户只是还没选东西 | 空状态 = 一句话 + 一个按钮 |
| 重复信息（同一句「已被 #4 取代」列表和详情各一次） | 噪音 | 一处就够，另一处只留标记 |
| 拼接出来的假状态（`active·已被#3取代`） | 两个字段硬拼，读起来像乱码 | 状态只允许**一个**维度，用颜色和一句话表达 |

## 4. 信息架构：从一个「大杂烩」改成三个视图

现在是一屏塞下全部（会话列表 + 对话 + 卡片表 + 详情 + 日志 + 两排按钮）。

改成 **1 个壳 + 3 个视图**：

```
┌─────────────────────────────────────────────────────────────┐
│ 知迹   概览 ·  决策地图 ·  一条决策        [项目 ▾] [设置 ⚙] │  顶部一条
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ① 概览 Overview（默认）   —— 结论 + 4 个数 + 可疑痕迹 + 关键决策
│   ② 决策地图 Map           —— 阶段条 + 每阶段的卡片 + 演进链
│   ③ 决策详情 Detail        —— 一条决策：为什么 / 还考虑过什么 / 代价 / 证据原文
│                                                             │
│   （会话原文、日志、全部卡片 → 抽屉，从右侧滑出，不占常驻版面）
└─────────────────────────────────────────────────────────────┘
```

- **概览**回答「现在能不能放心」——审查者和记录者都在这里满足。
- **决策地图**回答「这项目是怎么一步步走到今天的」——复盘者在这里。
- **详情**回答「凭什么这么说」——所有结论都必须能落到这里。
- **主界面只保留一个主动作**：右下角一个实心按钮，文案随上下文变
  （「生成这一段的决策」/「整理所有决策」/「复查这条」），其余动作收进 `⋯`。

## 5. 提示词正文（以下整段复制给生成平台）

---

你是一位做过数据类企业软件（尽调报告 / 审计工作台 / 研发看板）的资深产品设计师，
请在**一个单文件 HTML 原型**里，为下面的桌面软件设计完整新版界面。

### 5.1 产品是什么

**知迹 CogniTrail** —— 一个 Windows 桌面工具。它在 AI（Codex / WorkBuddy / Claude）
帮你干完活的**之后**运行，把这段时间里 AI 做的**决策**整理成可核对的记录。

- 它读的是这些 AI 工具自己写的会话文件，**不装插件、不改用户文件、不需要联网授权**。
- 它把会话提炼成一条条**决策记录**：做了什么 / 为什么 / 还考虑过什么 / 代价是什么。
- 每条记录都要钉住一个**证据坐标**（`文件:行号` + 一段原文摘录）——**定位不到就丢弃**。
- 它像**审计**一样核对：给出「审计意见」（无保留 / 带解释性说明 / 保留），
  并标出可疑痕迹（原有的校验被拿掉、异常被吞掉、凭据写死、用 `--no-verify` 绕过流程、
  断言和代码对不上）。
- 用户是**用 AI 干活的人**（工程师、研究者、写作者），不是审计专业人。
  他要的不是「一个更专业的审计工具」，是**「三个月后我还能回答上来，而且现在就能交差」**。

**请务必理解这个气质**：它更像一份「体检报告 + 病历」，不像一个「开发看板」。
可信、克制、能读、能抄。**不要做得像极客玩具。**

### 5.2 设计目标（按优先级）

1. **3 秒结论**：打开就知道「这批记录能不能照单全收」。
2. **一条路走到证据**：任何结论点两下就能看到文件原文那一行。
3. **能抄走**：任何一段文字都能选中复制；每条结论旁边有「复制」。
4. **说人话**：界面文案一律大白话，术语不许出现在主界面。
5. **安静**：主界面只有一处主色、一处强调色、一处警示色；其余是灰阶。
   信息可以多，但**视觉噪音必须少**。

### 5.3 交付物与技术要求

- **单文件 HTML**（内联 CSS / 少量原生 JS），双击就能在浏览器打开，无外部依赖。
- 视口按**桌面 1440 × 900** 设计，**不要做移动端适配**，不要做成竖屏手机界面。
- 三个视图用顶部标签切换，纯前端切换即可（不必真数据）。
- **必须用假数据把三个视图都填满**（数据见 5.9），不要出现「Lorem ipsum」或空白占位。
- 「详情」「看原文」「设置」做成从右侧滑出的抽屉（抽屉要能真实点开）。
- 文案、日期、路径一律用中文 / 真实感中文路径（如 `src/gui.py:426`）。

### 5.4 视觉方向

**基调**：档案室 / 体检报告。白底、大留白、细边框、清晰的分区线，
标题字重克制，等宽字体只用于坐标和代码。

- **不要**：暗色霓虹科技风、渐变紫蓝、玻璃拟态、圆润卡通、发光阴影、大面积彩色块。
- **要**：接近 `Linear` / `Stripe Dashboard` / `Notion` 的克制感，
  加一点「公文」的秩序感（对齐严谨、分区明确）。

**设计 token（请直接采用）**

| 用途 | 值 |
|---|---|
| 页面底色 | `#f6f7f9` |
| 卡片 / 面板 | `#ffffff` |
| 正文文字 | `#1b1f24` |
| 次要文字 | `#6b7280` |
| 提示文字 | `#9ca3af` |
| 分隔线 | `#e5e7eb` |
| 主色（品牌 / 正常） | `#0f766e`（深青），浅底 `#e6f4f2` |
| 警示（需要你看一眼） | `#b45309`，浅底 `#fef6e7` |
| 危险（可疑痕迹） | `#b42318`，浅底 `#fdecec` |
| 通过（无保留） | `#1a7f47`，浅底 `#f2fbf5` |
| 圆角 | 面板 14px / 小控件 8px / 标签 999px |
| 阴影 | 只用一层极淡的：`0 1px 2px rgba(16,24,40,.04)`；不要多层阴影 |
| 字体 | 中文用系统无衬线（`system-ui, "Microsoft YaHei"`）；坐标/代码用 `ui-monospace, Consolas` |
| 字号 | 正文 13px / 次要 12.5px / 区域标题 15px / **结论大字 26px** |
| 行高 | 正文 1.6；卡片标题 1.45 |

### 5.5 视图一：概览（默认打开，最重要）

自上而下：

1. **页头**：左「知迹」+ 当前项目名（如 `知迹 CogniTrail`）与卡片总数；
   右一个「项目」切换器、一个齿轮（设置）。
2. **结论区**（首屏最大的一块）：
   - 一行大字结论，例如 **「这批决策可以照单全收 · 无保留」**（26px，中粗）。
   - 下面一句解释（13px 灰）：如「12 条关键决策都有可核对的出处；2 条需要你自己看一眼」。
   - 右侧一个状态徽标，颜色按结论走（无保留 = 通过色 / 带解释性说明 = 警示色 / 保留 = 危险色）。
3. **四个数字块**（横排，可点，点了下面列表跟着筛）：
   `关键决策 12 条` · `需人工复核 2 条（其中存疑 1 条）` · `未审计 3 条` · `未取证 0 条`。
   数字块里必须体现包含关系（「存疑」是「需人工复核」的子集，用「其中」二字 + 缩进表示）。
4. **需要你看一眼**（只有存在时才出现）：逐条列可疑痕迹，
   例如「有一条改动绕过了检查流程（用了 `--no-verify`）」，右侧等宽坐标 `src/tools/build_exe.py:88`，
   行尾一个「看原文」。**不要用整块红色背景**，只用左侧 3px 红线和浅底标签。
5. **关键决策**（3～5 张卡，宽卡）：每张卡
   - 左侧 3px 主色竖线表示「关键」；
   - 主标题 = 这条决策做了什么（一句话，允许两行）；
   - 下面两行：`为什么` 一行、`代价` 一行（各截断到一行，超出省略）；
   - 底部一行次要信息：阶段标签 + 来源（Codex / Claude）+ 坐标 + 时间 + 一个「复制」；
   - 卡片右上角一个折叠三角「为什么 / 还考虑过什么 / 证据」，点了原地展开。
6. **页脚一行**：`共 43 条记录 · 最近更新 10-16 14:22 · 查看全部`（点了进视图二）。

### 5.6 视图二：决策地图

1. **阶段条**（横向，等宽，像地铁线路）：
   `S1 立项` → `S2 打通模型通道` → `S3 卡片审计化` → `S4 界面重做`，
   当前阶段加重色下划线；每段下面小字 `7 条`。
2. **每阶段一节**（手风琴，默认全开）：
   - 节头：阶段名 + 该阶段「卡在什么问题」一句话 + 条数；
   - 节内按时间排的卡片（窄卡，一行一条），每条：
     决策一句话 / 坐标 / 状态点。
3. **演进链**（单独一块，放在对应阶段末尾）：
   用「早期做法（灰、删除线）→ 为什么被否（一句 + 警示色小标签）→ 现在的做法（主色）」三联，
   中间用箭头连起来。**这是本产品最独特的价值，必须比普通卡片更显眼一点。**
4. **已作废的卡片**：整体降到 45% 不透明度 + 灰标签「已被 #7 取代」，不删除。

### 5.7 视图三：一条决策（详情抽屉或整页）

- 顶部：一句标题（决策本身）+ 右侧「复制这一段」。
- 主体按固定顺序：
  1. **在项目里的位置**：项目 › 阶段（可点，回视图二）
  2. **这一步的问题**：当时卡在哪
  3. **为什么这么定**（正文，占最大空间）
  4. **还考虑过什么**：逐条列出被否的选项 + 被否原因
  5. **代价与风险**
  6. **它推翻了**：早期做法 + 为什么推翻（如果本条是演进链的一环）
  7. **证据**（折叠可展开）：等宽代码块显示原话摘录，行首标注 `src/gui.py:426`；
     右上角「在文件里打开」。
  8. **专家细节**（最底部、默认折叠）：状态 / 来源 / 写法档位 / 创建时间 / 文件路径。
- 抽屉里不允许出现「没有内容」的空字段 —— 没写的字段整行不出现。

### 5.8 文案规范（很重要，请当成硬约束）

界面上**任何**给用户看的字都要遵守：

- 说人话，不说术语。出现以下词必须换掉：
  | 不要写 | 写成 |
  |---|---|
  | quote 闸门未通过 | 有 3 条决策没能在文件里找到出处，已经丢掉 |
  | 未取证 | 没找到原文出处 |
  | 疑似反舞弊痕迹：绕过流程 | 有一条改动绕过了检查流程（用了 `--no-verify`） |
  | verdict: fail | 这条断言和代码对不上 |
  | superseded | 已被后面的做法取代 |
  | tier: key | 关键决策 |
  | tone: pro / plain | 专家模式 / 小白模式 |
- 数字不能只说结论，要说清「其中多少是自己人」（例如「需人工复核 2 条，其中 1 条存疑」）。
- 不确定就说不确定：`未审计` 不是 `没问题`。
- 不要把两个状态拼在一起（不要出现 `active·已被#3取代`）。
- 界面本身也要有**两档写法**：一个「专家模式 / 小白模式」切换，
  切换后同一张卡片的正文口吻跟着变（小白模式：「网络不好时不再反复等，直接给一个空结果」；
  专家模式：「在 `load_config()` 里把 timeout 的默认值由 30 改成 60」）。
  **换的只是措辞，坐标和数字一个字都不许变。**

### 5.9 用这些假数据填满界面

```text
项目：知迹 CogniTrail      共 43 条记录      最近更新 2026-10-16 14:22
审计意见：带解释性说明（不是无保留）
关键决策 12 条 · 需人工复核 2 条（其中存疑 1 条）· 未审计 3 条 · 未取证 0 条

【需要你看一眼】
1. 有一条改动绕过了检查流程（用了 --no-verify 提交）
   坐标 tools/build_exe.py:88   来源 Codex
2. 有一条断言和代码对不上：卡片说「默认 60 秒」，文件里是 30
   坐标 src/config.py:214        来源 WorkBuddy

【关键决策 · 3 例】
D-20261014-173936 ｜ 阶段 S2 打通模型通道 ｜ 来源 WorkBuddy
  做了什么：绕过 AI 工具自带的代理，改用本机香港节点直连模型接口
```

### 5.10 禁止清单

- 不要暗色主题、不要渐变、不要玻璃拟态、不要发光、不要彩色大面积色块。
- 不要圆角超大、不要卡通插画、不要 emoji 当图标（用线性 SVG 图标或纯文字）。
- 不要把日志、文件路径、机器字段放在首屏。
- 不要「仪表盘式」的一堆圆环 / 折线图 —— 这个产品的数据不是趋势，是**一批待核对的条目**。
  真的需要图，最多用一个横向的阶段进度条。
- 不要用红绿二色表达「好坏」以外的意思；不要在中文界面里夹英文标签（`Overview` / `Detail`）。
- 不要把「未审计」显示成绿色或打勾。

### 5.11 验收标准（请自检后再交付）

1. 首屏 3 秒内能说出「是否可以照单全收」，以及「有几条要我自己看」。
2. 从任意一条结论，最多点 2 次能看到 `文件:行号` 的原文片段。
3. 主界面出现的术语为 0；出现的机器字段为 0（都在折叠里）。
4. 主界面只有 1 个实心按钮（主动作），其余是文字按钮或折叠。
5. 切换「专家模式 / 小白模式」后，同一张卡片的措辞变化很明显，但坐标和数字完全不变。
6. 空状态是「一句话 + 一个按钮」，不是一段说明书。
7. 所有正文都能选中复制，且每条决策有独立的「复制」。

## 6. 精简版（给有长度限制的平台）

> 为「知迹 CogniTrail」这个 Windows 桌面工具设计新版界面，输出**单文件 HTML 原型**
> （内联 CSS，1440×900 桌面端，三个视图用顶部标签切换，用真实感中文假数据填满）。
>
> 它做什么：在 AI 帮你干完活之后，把这段时间的**决策**整理成可核对的记录 ——
> 每条记录说清「做了什么 / 为什么 / 还考虑过什么 / 代价」，并钉住一个证据坐标
> （`文件:行号` + 原文摘录），找不到出处的直接丢弃；它像审计一样给出结论
> （无保留 / 带解释性说明 / 保留）并标出可疑痕迹。
>
> 用户是想「三个月后还能回答上来」的普通人，不是审计专业人。气质要像**体检报告 / 病历**：
> 可信、克制、能读、能抄；**不要极客玩具**。
>
> 三个视图：① **概览** —— 首屏最大的字给「能不能照单全收」，
> 下面一排四个数字（关键决策 / 需人工复核（其中存疑）/ 未审计 / 未取证），
> 再下面「需要你看一眼」的可疑痕迹，再下面 3～5 张关键决策卡（可原地展开）。
> ② **决策地图** —— 横向阶段条 + 每个阶段的卡片 + **演进链**（早期做法为什么被否 → 现在的做法）。
> ③ **一条决策** —— 为什么 / 还考虑过什么 / 代价 / 证据原文（`文件:行号` + 代码块），
> 机器字段折在最底部。
>
> 硬约束：白底 `#f6f7f9`、面板白、正文 `#1b1f24`、主色深青 `#0f766e`、
> 警示 `#b45309`、危险 `#b42318`、通过 `#1a7f47`；只用一层极淡阴影；
> **不要**暗色 / 渐变 / 玻璃拟态 / 发光 / 大色块 / 圆环图表 / emoji 图标 / 英文标签。
> 界面上**不许出现术语**（闸门、quote、tier、verdict、superseded 一律换成人话）。
> 主界面只留 1 个实心按钮（主动作），日志和文件路径不许出现在首屏。
> 提供一个「专家模式 / 小白模式」切换：切换后措辞明显变化，但坐标和数字一字不变。

## 7. 拿到设计稿之后怎么用

1. 先看**信息层级**对不对：首屏是不是只有「结论 + 数字 + 可疑 + 关键决策」四件东西。
2. 再对照第 3 节的取舍表逐条打勾 —— 任何「不想看」的内容出现在首屏，直接退回去改。
3. 这份设计如果要落到现在的 Tk 界面（`src/gui.py`），注意：
   Tk 没有圆角 / 阴影 / 动画，**能等价实现的是**分区、字号层级、颜色、
   折叠（`ttk.Treeview` 或「展开 / 收起」按钮）、抽屉（`Toplevel` 子窗口）。
   所以设计稿里的「描边 + 留白 + 字号层级」可以照搬，
   靠阴影和透明度做出的层次感要在落地时换成「细边框 + 背景色差」。
